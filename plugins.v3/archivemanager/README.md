# 压缩归档

文件压缩归档，支持独立清单、校验和可选加密。

> 兼容性：MoviePilot v3.x（最低版本：v3.0.0）
> 适用场景：本地文件归档、外部上传工具接力、独立清单管理

## 功能概览

- 扫描本地普通文件和真实目录，支持递归、包含与排除 glob、文件保留天数和稳定性观察
- 按目录、文件修改日期或两者组合分组，再按文件数量和源文件体积拆分批次
- 支持 7z、ZIP、四档压缩级别、AES-256 内容加密和完整读回校验
- 保留文件名、相对路径、文件内容、修改时间、权限、目录结构及空目录；文件系统支持时记录创建时间
- 归档包内包含 `manifest.md`、`manifest.json` 和 `SHA256SUMS`，包外另存明文清单、索引和归档 SHA-256
- 支持批次清理、补全清单、失败重试、任务复制、源文件空间回收和运行数据重置
- 多个任务可以共用输出目录和清单目录，清单按任务分目录保存

插件只处理 MoviePilot 容器可访问的本地路径。外部上传、远端校验和云端成品管理由其他工具负责。

## 定时服务

每个已启用的任务注册一个 `压缩归档 · <任务名>` Cron 服务。Cron、日期分组和名称变量均使用容器时区。

启用“自动续跑”后，插件另注册 `压缩归档 · 自动续跑` 服务，每 20 分钟检查一次。它只继续用户已经启动且因空间或本地成品上限暂停的归档周期，不会自动重试运行失败的批次。

预览、归档、重试、补全清单和空间回收共用一个串行工作队列。同一任务被重复提交时会复用已经运行或排队的作业。

## API

以下路径均为 `ArchiveManager` 插件 API 下的相对路径，并使用 MoviePilot 宿主认证。

| 方法 | 相对路径 | 说明 |
| --- | --- | --- |
| `GET` | `/summary` | 查询统计、任务状态、队列和配置错误 |
| `GET` | `/batches` | 分页查询批次，支持按任务和状态筛选 |
| `GET` | `/batch` | 查询单个批次详情 |
| `GET` | `/files` | 按任务、目录、状态和相对路径查询文件 |
| `POST` | `/preview` | 提交只读预览 |
| `GET` | `/preview` | 查询预览结果 |
| `POST` | `/run` | 运行单个任务；不指定任务时运行所有任务 |
| `POST` | `/stop` | 停止单个任务；不指定任务时停止全部任务和队列 |
| `POST` | `/retry` | 重试失败或未完成的批次 |
| `POST` | `/repair` | 根据数据库快照补全包外清单 |
| `POST` | `/reclaim/preview` | 统计可回收的源文件和孤儿暂存 |
| `POST` | `/reclaim` | 提交源文件空间回收并清理孤儿暂存 |
| `POST` | `/cleanup` | 清理批次记录，可选同步删除归档产物和包外清单 |

预览只扫描和分批，不创建归档包、不写入清单，也不删除源文件。

### 5. 压缩与完成

| 配置项 | 标识 | 类型 | 默认值 | 说明 | 备注 |
| --- | --- | --- | --- | --- | --- |
| [格式](#cfg-format) | `format` | enum | `7z` | 选择 7z 或 ZIP | ZIP 不支持加密文件名 |
| 压缩级别 | `compression` | enum | `normal`（标准） | 选择存储、快速、标准或高压缩 | 压缩越高通常耗时越长 |
| [加密](#cfg-encryption) | `encryption` | enum | `none`（不加密） | 选择不加密或 AES-256 | AES-256 必须填写密码 |
| 密码 | `password` | string | 空 | AES-256 归档密码 | 只写入、不回显、不进入清单 |
| 密码版本 | `password_version` | string | `1` | 标识批次使用的密码版本 | 恢复加密批次时必须匹配 |
| 加密文件名 | `encrypt_names` | bool | `false` | 隐藏 7z 包内成员名称 | 仅支持 7z + AES-256 |
| 完成校验 | `verify` | bool | `true` | 发布前读回并核对成员和元数据 | 删除源文件时强制开启 |
| [删除源文件](#cfg-delete_source) | `delete_source` | bool | `false` | 完成归档后逐文件删除源文件 | 仅在校验和清单完成后执行 |

## 命名变量

“批次名称”和“归档包名称”支持以下变量：

| 变量 | 值 |
| --- | --- |
| `{task_name}` | 任务名，文件名非法字符替换为 `_` |
| `{date}` | 批次创建日期，格式 `YYYYMMDD` |
| `{time}` | 批次创建时间，格式 `HHMMSS` |
| `{id}` | 批次 ID 前 6 位 |
| `{sequence}` | 当前任务当天递增的六位序号 |
| `{global_sequence}` | 所有任务当天共享递增的六位序号 |
| `{%Y%m%d_%H%M%S}` | 使用 Python `strftime` 格式化批次创建时间 |
| `{file_mtime}` | 批次内最早文件修改时间，格式 `YYYYMMDD_HHMMSS` |
| `{file_mtime:%Y%m%d_%H%M%S}` | 使用 Python `strftime` 格式化最早文件修改时间 |

所有日期和时间均使用容器时区。模板不能生成路径，也不能包含文件名保留字符。归档包扩展名由“格式”自动追加；文件名主体超过 180 个 UTF-8 字节时不会创建成品。

<a id="cfg-source_dir"></a>
### 源目录（`source_dir`）

只处理普通文件和真实目录，不跟随符号链接。包含规则为空时接收所有普通文件；排除规则始终优先。无法读取、特殊类型、规则排除、修改时间过新或稳定性检查失败的文件会计入预览的“跳过文件”。

<a id="cfg-grouping"></a>
### 文件分组（`grouping`）

- `none`：全部候选文件进入同一组
- `directory`：按相对父目录分组，最多取“目录深度”指定的层级
- `date`：按文件 `mtime` 和“时间粒度”分组
- `directory_date`：同时按目录与文件 `mtime` 分组

每组仍会继续受“每批文件数”和“每批体积”限制。

<a id="cfg-batch_name_template"></a>
### 批次名称（`batch_name_template`）

批次名称用于页面、清单和输出目录。若按目录布局，成品路径为 `来源分组/批次名称/归档包`；扁平布局会用下划线连接来源分组和批次名称。

需要跨任务避免同名时可使用 `{file_mtime}_{global_sequence}`；需要直接辨认任务时可使用 `{task_name}_{file_mtime}_{global_sequence}`。

<a id="cfg-archive_name_template"></a>
### 归档包名称（`archive_name_template`）

归档包名称只控制最末级文件名，不包含 `.7z` 或 `.zip`。可使用 `{file_mtime}_{global_sequence}_{id}` 同时保留可读时间、全局序号和批次标识。

<a id="cfg-archive_age_days"></a>
### 文件保留天数（`archive_age_days`）

默认 `7` 表示只处理 `mtime <= 当前时间 - 7 天` 的文件。它不是“最近 7 天内的文件”，也不使用创建时间。修改此值后，下一次扫描会按新条件重新判断现场文件。

<a id="cfg-max_pending_archives"></a>
### 成品批次上限（`max_pending_archives`）

限制输出目录中仍存在的已发布成品数量，不限制数据库历史记录或源文件数量。外部工具移走成品后，本地占用会下降，但插件不会因此判断上传已经成功。

<a id="cfg-auto_continue"></a>
### 自动续跑（`auto_continue`）

适合由外部工具持续移走归档成品的场景。插件每 20 分钟检查本地成品数量、体积和输出卷空间，条件恢复后继续此前已启动的周期。运行失败的批次仍需用户手动重试。

<a id="cfg-min_free_bytes"></a>
### 预留空间（`min_free_bytes`）

开始构建前，输出卷需要容纳本批源文件体积、额外工作空间和配置的预留空间。暂存目录固定在输出目录同级的 `.archivemanager-staging`，因此输出目录必须是卷内子目录，并与暂存目录位于同一文件系统。

<a id="cfg-format"></a>
### 格式（`format`）

7z 的存储模式不压缩，其他档位使用 LZMA2。ZIP 的存储模式不压缩，其他档位使用 DEFLATE。两种格式都保存相同的源文件路径和清单；包含字面反斜杠（`\`）的文件名需使用 ZIP。

<a id="cfg-encryption"></a>
### 加密（`encryption`）

AES-256 会加密文件内容。只有 7z 可以同时启用“加密文件名”。密码不会写入任务运行快照、归档清单或通知，需由用户自行保管；恢复历史加密批次时，当前任务的密码和密码版本必须与批次一致。

<a id="cfg-delete_source"></a>
### 删除源文件（`delete_source`）

开启后，插件会强制执行完整校验，并在归档包、包外清单和数据库状态均完成后逐文件处理。删除前会再次核对归档包 SHA-256、源文件身份和内容 SHA-256：

- `deleted`：源文件匹配并已删除
- `missing`：源文件已经不存在
- `changed`：源文件发生变化，保留当前文件
- `failed`：没有权限删除，保留当前文件

关闭此项完成归档后，也可以在概览点击“回收空间”。确认框会先统计可回收批次、文件和预计空间，再把仍存在且校验通过的源文件加入回收队列。归档包和清单不会被删除。

## 使用步骤

1. 安装插件并开启“启用插件”
2. 新建任务，填写源目录、输出目录、清单目录和 Cron
3. 设置文件范围、分组、批次上限、格式与完成行为，点击“保存草稿”
4. 点击页面顶部“保存修改”，将插件配置和所有任务一起写入宿主配置
5. 先用“预览文件”核对候选文件、跳过数量、目录分组和预计批次
6. 点击“运行一次”执行当前任务，或点击页面顶部“提交全部任务”将所有任务一起提交
7. 在批次页确认状态、归档 SHA-256、包外清单和源文件清理结果

## 批次维护与数据管理

- **重试**：重新执行失败、取消或未完成的批次；任务配置或源文件版本变化时，旧批次可能标记为已替代并重新分批
- **补全清单**：归档包和数据库快照仍可用时，重新生成包外 Markdown、JSON 和索引
- **清理批次**：可只清理数据库记录，也可在二次确认后同时删除归档包、`.sha256` 和对应包外清单；源文件始终不受影响
- **回收空间**：扫描所有已完成批次，删除仍保留且与归档快照完全一致的源文件，同时清理不可恢复的孤儿暂存
- **重置数据**：清空批次、文件、目录和任务运行状态；保留插件配置、任务配置、归档包和包外清单

清理归档产物后，插件会删除批次路径上已经为空的输出子目录，但保留配置的输出根目录。包外清单删除后会重建任务索引和共享根索引。

## 归档内容与恢复

每个归档包固定包含：

```text
files/
manifest.md
manifest.json
SHA256SUMS
```

`files/` 保留源文件的完整相对路径和目录结构。`manifest.json` 记录文件与目录的修改时间、权限、可用的文件系统创建时间、源文件身份和 SHA-256。归档格式本身保存修改时间和权限；ZIP 还会在支持的平台记录创建时间。标准解压工具对创建时间和权限的实际恢复能力取决于格式、工具和目标文件系统，清单可用于补恢复与核对。

`SHA256SUMS` 严格覆盖所有源文件成员以及包内两份清单。输出目录中的 `<归档包>.sha256` 校验归档文件本身。外部清单位于 `清单目录/<任务名>/`，每批包含 `manifest.md` 和 `manifest.json`，并生成任务级与共享根级 `index.md`、`index.json`。

恢复时先校验归档包旁的 `.sha256`，再解压到独立目录，在包含 `SHA256SUMS` 的目录运行：

```bash
sha256sum -c SHA256SUMS
```

macOS 可使用：

```bash
shasum -a 256 -c SHA256SUMS
```

## 注意事项

- 归档包在同级 `.archivemanager-staging/<任务 ID>/<批次 ID>/` 中构建，完成后通过同一文件系统内的原子重命名发布
- 手动停止会终止当前工作进程并清理该批次未发布的暂存；已经发布的归档包和清单保留
- 重启后会优先恢复数据库中未完成且仍可验证的批次，不会覆盖已经发布的同一批次成品
- 已发布成品被外部移走后不会重新打包；需要补清单时应恢复原归档包，或在数据库快照仍完整时使用“补全清单”
- 开启“删除源文件”具有破坏性，建议先完成一次不删除源文件的归档与恢复验证
- 数据库是页面状态和续跑依据，包外清单是独立归档记录；重置或清理数据库前应确认不再需要从页面管理对应批次

## 故障排查

- 主日志：`MoviePilot/config/logs/moviepilot.log`
- 插件日志：`MoviePilot/config/logs/plugins/archivemanager.log`
- **配置未生效**：检查概览中的配置错误，确认三个目录均为绝对路径、互不重叠且 Cron 有效
- **任务等待空间**：检查“成品批次上限”“成品体积上限”“预留空间”和输出卷实际可用空间
- **大量文件被跳过**：在日志中查找 `压缩归档扫描统计`，分别查看 `pattern`、`too_new`、`unreadable_or_special` 和 `unstable`
- **批次待补全清单**：确认归档包仍在原位置，再使用批次详情中的“补全清单”
- **源文件清理失败**：检查批次详情中的清理结果、源文件是否变化以及 MoviePilot 对源目录的删除权限
- **加密批次恢复失败**：恢复该批次使用的密码，并将当前任务的“密码版本”改回批次记录的版本
