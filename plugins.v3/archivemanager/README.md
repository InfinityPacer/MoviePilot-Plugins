# 压缩归档

通用文件分批压缩、可选加密、完整校验与独立归档清单，适合需要把本地普通文件整理成可校验、可恢复归档的场景。

> 兼容性：MoviePilot v3.x（最低版本：v3.0.0）
> 适用场景：本地文件归档、外部上传器接力、独立清单管理

## 版本更新日志

- v0.1.0
  - 新增按目录和修改时间分组的分批归档。
  - 支持 7z、ZIP、可选 AES-256 加密和完整读回校验。
  - 归档包内写入 `manifest.md`、`manifest.json` 和 `SHA256SUMS`，并在包外保存独立明文清单与归档 SHA-256。

## 功能概览

归档索引使用主程序管理的插件独立数据库。SQLite 使用插件数据目录中的 `plugin.db`；PostgreSQL 使用主程序分配的独立 schema。主程序在插件启动前执行 Alembic 迁移，创建或升级 `archive_batch`、`archive_file`、`archive_task`，并用 `alembic_version` 记录结构版本。停止插件只释放连接，删除插件数据才会销毁对应数据库。包外清单独立保存，不依赖此数据库读取。

- 扫描任意本地普通文件，支持递归目录、包含/排除 glob、归档年龄和稳定性观察。
- 按目录、修改日期或目录与日期组合分组，再按每批文件数和源字节数拆分归档。
- 可分别配置批次显示名和归档文件名模板；批次目录支持按目录或扁平布局，包外清单目录使用任务显示名，内部任务 ID 和批次 ID 只作为 JSON 与数据库关联键保存。
- 首次实际运行会持久化通过年龄和稳定性条件的历史清单；后续优先处理历史待办，历史失败等待重试，变化或缺失单独记录后再处理新增文件。
- 通过本地成品最多批次、本地成品最大体积和 `预留磁盘空间` 限制积压；可选在外部移走成品且空间满足时每 60 秒继续处理。
- 支持 7z 与 ZIP；压缩级别可选存储、快速、标准或高压缩。
- 可选 AES-256 内容加密；7z 还可以加密文件名，ZIP 不支持文件名加密。
- 归档包内包含源文件、两份清单和严格的 `SHA256SUMS`；包外另保存归档本身的 SHA-256 与独立明文清单。
- 源文件清理是可选动作，只会在完整校验、清单完成且源文件仍与归档快照匹配后逐文件执行；插件不负责上传，也不会自动删除归档成品或包外清单。
- 不跟随符号链接，不负责 NAS 状态或云端成功确认。

## 定时服务

每个启用任务注册一个独立 Cron 服务，服务名称为 `压缩归档 · <任务名称>`，周期和时区取自该任务的 `Cron 调度` 与 `时区`。同一插件实例内的预览、运行和恢复操作使用单工作队列串行执行；重复触发同一任务时会合并，不会并行创建同一任务的批次。开启 `自动分批续跑` 后，外部移走已发布成品且输出卷达到 `预留磁盘空间` 要求时，任务最多每 60 秒继续处理待办。

## API

以下路径是 `ArchiveManager` 插件 API 入口下的相对路径，均使用 MoviePilot 宿主认证（`bear`）。实际宿主前缀由 MoviePilot 路由提供。

| 方法 | 相对路径 | 说明 |
| --- | --- | --- |
| `GET` | `/summary` | 归档统计、运行状态、排队任务和配置错误 |
| `GET` | `/batches` | 分页查询批次；支持 `task_id`、`status`、`page`、`page_size` |
| `GET` | `/batch` | 查询批次详情；需要 `batch_id` |
| `GET` | `/files` | 分页查询归档文件；支持 `task_id`、`directory`、`query`、`status`、`page`、`page_size` |
| `POST` | `/preview` | 提交只读预览；请求体为 `{ "task": { ... } }` |
| `GET` | `/preview` | 查询预览结果；需要 `job_id` |
| `POST` | `/run` | 运行任务；请求体为 `{ "task_id": "..." }` |
| `POST` | `/stop` | 请求停止；请求体可带 `task_id`，留空表示停止当前运行 |
| `POST` | `/retry` | 重试批次；请求体为 `{ "batch_id": "..." }` |
| `POST` | `/repair` | 补全外部清单；请求体为 `{ "batch_id": "..." }` |

所有响应使用 MoviePilot 的统一响应包装。预览只扫描和分批，不创建归档、不写入清单，也不删除源文件。

| 配置项 | 标识 | 类型 | 默认值 | 说明 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 本地成品最多批次 | `max_pending_archives` | integer | `1` | 限制本地仍存在的成品批次 | `0` 表示不限 |
| 本地成品最大体积 | `max_pending_bytes` | integer | `0` | 限制本地成品总字节数 | `0` 表示不限，单位为字节 |
| 预留磁盘空间 | `min_free_bytes` | number（GiB） | `1` | 归档后要求保留的输出卷空间 | 输入单位为 GiB；`0` 表示不预留 |
| 自动分批续跑 | `auto_continue` | bool | `false` | 外部移走成品后继续当前周期 | 每 60 秒检查一次，仍受空间和成品上限约束 |

`分组方式` 的值含义如下：`none` 为全部文件一组，`directory` 按相对父目录分组，`date` 按 `mtime` 日期分组，`directory_date` 同时使用目录和日期。目录分组最多使用 `目录深度` 层；时间分组使用 `时区` 转换后的 `mtime`。`归档多少天之前的文件` 以当前时间减去天数得到截止点，只接收 `mtime` 不晚于该截止点的文件；`稳定时间（秒）` 仍用于打包前后确认源文件身份没有变化。

### 命名规则

`批次名称模板` 和 `归档文件名模板` 只允许使用简单占位符 `{task_name}`、`{date}`、`{id}`，不支持路径分隔符、文件名保留字符、控制字符、格式说明（例如 `{date:>30}`）或转换标记（例如 `{id!r}`）。模板不能为空，模板文本最多 160 个字符。

- `{task_name}`：使用任务名称；用于生成名称时会把文件名非法字符替换为 `_`，任务在页面和清单中的原始显示名不变。
- `{date}`：使用批次创建时间转换到任务 `时区` 后的时间，格式固定为 `YYYYMMDD-HHMMSS`，例如 `20260911-040000`。
- `{id}`：使用批次完整内部 ID。
- `归档文件名模板` 的扩展名由 `归档格式` 自动追加为 `.7z` 或 `.zip`。模板结果不含 `{id}` 时，文件名主体末尾自动追加 `--<完整批次 ID>`；默认 `{id}` 因此直接生成 `<完整批次 ID>.<格式>`。
- 生成的归档文件名主体（包括自动追加的完整 ID，不包括自动扩展名）超过 180 个 UTF-8 字节时，任务会报错并不会创建该批次的成品。
- 每个批次创建时冻结两种名称；之后修改模板只影响新批次，不会重命名、移动或重建已有批次。输出目录使用可读的分组名与批次名，包外清单目录额外使用任务显示名；同名任务会追加可读数字后缀（例如 `相机归档 (2)`），完整内部 ID 仅保存在 JSON、数据库和运行接口中。
- 7z 的 `加密文件名（7z）` 只隐藏归档包内部成员名，不隐藏输出目录、归档文件外层名称、包外 `.sha256` 或清单文件中的名称。

### 压缩与安全

| 配置项 | 标识 | 类型 | 默认值 | 说明 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 归档格式 | `format` | enum | `7z` | 选择归档容器 | 可选 `7z`、`zip` |
| 压缩级别 | `compression` | enum | `normal`（标准） | 选择压缩档位 | 可选 `store`、`fast`、`normal`、`high` |
| 加密方式 | `encryption` | enum | `none`（不加密） | 选择内容加密 | 可选 `none`、`aes256` |
| 密码（可选） | `password` | string | 空 | AES-256 归档密码 | 加密时不能为空；不写入清单 |
| 密码版本 | `password_version` | string | `1` | 标识当前密码版本 | 恢复历史加密批次时必须匹配 |
| 加密文件名（7z） | `encrypt_names` | bool | `false` | 是否隐藏 7z 文件名 | 仅适用于 7z + AES-256 |

7z 的 `store` 使用存储模式，其余档位使用 LZMA2；ZIP 的 `store` 不压缩，其余档位使用 DEFLATE。ZIP 可以使用 AES-256 加密内容，但不支持加密文件名。

### 完成行为

| 配置项 | 标识 | 类型 | 默认值 | 说明 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 归档后校验 | `verify` | bool | `true` | 发布前读回并校验全部成员 | 删除源文件时强制开启 |
| 校验通过后删除源文件 | `delete_source` | bool | `false` | 完成后逐文件清理源文件 | 仅在校验、清单和源文件复核均通过后执行 |

## 深入说明

<a id="cfg-source_dir"></a>
#### 源目录（`source_dir`）

- **解决什么问题**：定义本次任务读取文件的边界。
- **什么时候开 / 不开**：填写 MoviePilot 可以访问的绝对普通目录；不存在、经过符号链接或与其他任务输出重叠时，任务不会运行。
- **典型联动**：`递归扫描子目录`、`包含模式`、`排除模式` 和 `归档多少天之前的文件` 共同决定候选源文件。
- **示例**：`/data/source`
- **常见误用**：把归档输出目录或清单目录放在源目录内，会被路径边界校验拒绝。

<a id="cfg-grouping"></a>
#### 分组方式（`grouping`）

- **解决什么问题**：控制多个源文件如何形成批次，避免一次运行生成过大的单个归档。
- **什么时候开 / 不开**：按目录归档时使用 `directory`；按修改时间归档时使用 `date`；需要两者共同隔离时使用默认的 `directory_date`；不需要分组时使用 `none`。
- **典型联动**：目录模式受 `目录深度` 影响，日期模式受 `时间粒度` 和 `时区` 影响；每组仍会继续受文件数和字节数限制。
- **示例**：`grouping=directory_date`、`directory_depth=1`、`time_grain=day`。
- **常见误用**：把文件创建时间当成分组依据；首版按文件 `mtime` 分组。

<a id="cfg-batch_name_template"></a>
#### 批次名称模板（`batch_name_template`）

- **解决什么问题**：为批次提供便于页面、清单和索引阅读的可读名称，同时保留完整内部 ID 作为稳定关联键。
- **什么时候开 / 不开**：默认使用 `{task_name}_{date}`；不需要自定义显示名时保持默认即可。
- **典型联动**：`{task_name}` 会把任务名中的文件名非法字符替换为 `_`；`{date}` 使用批次创建时间和任务 `时区`，不是源文件 `mtime`。
- **示例**：`{task_name}_{date}` 生成 `报告_资料_20260911-040000`。
- **常见误用**：把它当作输出目录或清单文件路径；输出目录中的批次目录和包外清单目录均按可读名称组织，完整内部 ID 只用于机器关联。

<a id="cfg-archive_name_template"></a>
#### 归档文件名模板（`archive_name_template`）

- **解决什么问题**：为输出目录内的归档包提供可读文件名，同时保留批次 ID 以避免跨批次重名。
- **什么时候开 / 不开**：默认使用 `{id}`；需要任务名或创建时间出现在文件名中时再自定义。
- **典型联动**：扩展名由 `归档格式` 自动追加；模板不含 `{id}` 时自动追加 `--<完整批次 ID>`，已有批次不会因模板变化而改名。
- **示例**：`备份_{date}` 会生成类似 `备份_20260911-040000--<完整批次 ID>.7z`。
- **常见误用**：把 7z 头加密理解为隐藏外层文件名；它只隐藏包内成员名。模板结果还必须符合文件名约束，并在主体超过 180 个 UTF-8 字节时缩短。

<a id="cfg-archive_age_days"></a>
#### 归档多少天之前的文件（`archive_age_days`）

- **解决什么问题**：把仍可能持续写入的近期文件留在源目录，优先归档已经经过设定天数的文件。
- **什么时候开 / 不开**：默认 `7`，表示只处理 `mtime <= 当前时间 - 7 天` 的普通文件；需要更快接力时可降低天数，但仍会经过稳定性观察。
- **典型联动**：和 `稳定时间（秒）` 一起保护打包期间的变化；它按 `mtime` 判断年龄，不使用创建时间。
- **示例**：`archive_age_days=7`、`stability_seconds=60`。
- **常见误用**：把它当成“最近 N 天内归档”；实际含义是只接收当前时间往前至少 N 天的文件。

<a id="cfg-max_pending_archives"></a>
#### 本地成品最多批次（`max_pending_archives`）

- **解决什么问题**：限制本地仍存在的已发布成品批次，避免外部工具未及时移走时继续堆积成品。
- **什么时候开 / 不开**：默认 `1`；希望持续接力并由空间和外部工具自行承担积压时设为 `0` 不限。
- **典型联动**：和 `本地成品最大体积`、`预留磁盘空间` 共同决定是否允许开始下一批；历史待办优先于新增文件。
- **示例**：`max_pending_archives=1`、`max_pending_bytes=0`、`min_free_bytes=1 GiB`。
- **常见误用**：把它理解为源文件数量或数据库待办数量；这里限制的是仍留在输出目录中的本地成品批次。

<a id="cfg-auto_continue"></a>
#### 自动分批续跑（`auto_continue`）

- **解决什么问题**：让外部工具移走成品后，插件可以继续处理已持久化的历史清单和后续新增文件。
- **什么时候开 / 不开**：默认关闭；只有外部工具明确负责读取输出目录并移走成品时才开启。插件仍不判断上传是否成功。
- **典型联动**：每 60 秒检查一次；必须同时满足成品已不在本地、输出卷剩余空间达到 `预留磁盘空间`、本地成品批次和体积未超限。
- **示例**：`auto_continue=true`、`max_pending_archives=1`、`min_free_bytes=1 GiB`。
- **常见误用**：成品消失并不等于上传成功；外部工具移走错误文件时，插件不会替它确认远端状态。

<a id="cfg-min_free_bytes"></a>
#### 预留磁盘空间（`min_free_bytes`）

- **解决什么问题**：为归档暂存和输出卷保留用户指定的安全余量，避免压缩过程把卷写满。
- **什么时候开 / 不开**：默认输入 `1`（GiB）；输入 `0` 表示不额外预留。没有足够空间时不会开始新的归档构建。
- **典型联动**：和 `本地成品最多批次`、`本地成品最大体积` 一起计算下一批可用预算；暂存目录和输出目录必须位于同一文件系统。
- **示例**：`预留磁盘空间=1`（GiB）、`output_dir=/archive/ready`。
- **常见误用**：直接选择独立卷挂载根作为输出目录；应选择卷内子目录，让旁边的 `.archivemanager-staging` 能在同一卷工作。

<a id="cfg-format"></a>
#### 归档格式（`format`）

- **解决什么问题**：选择归档容器和恢复端需要使用的工具。
- **什么时候开 / 不开**：默认使用 7z；需要更广泛的 ZIP 工具兼容性时选择 ZIP。两种格式都包含相同的文件路径和校验清单。
- **典型联动**：`压缩级别` 对 7z 使用存储/LZMA2 档位，对 ZIP 使用存储/DEFLATE 档位；`加密文件名（7z）` 只能与 7z + AES-256 组合。
- **示例**：普通归档使用 `format=7z`、`encryption=none`；兼容 ZIP 工具时使用 `format=zip`。
- **常见误用**：在 ZIP 上启用文件名加密；前端会提示切换，后端也会拒绝该组合。

<a id="cfg-encryption"></a>
#### 加密方式（`encryption`）

- **解决什么问题**：保护归档内容，避免归档文件被直接读取。
- **什么时候开 / 不开**：无密码保管要求时保持 `none`；需要加密时选择 `aes256` 并填写 `密码（可选）`。密码不会进入归档快照或任何包内、包外清单。
- **典型联动**：`密码版本` 用于恢复历史批次；启用 `校验通过后删除源文件` 时仍会先使用密码读回校验。
- **示例**：`format=7z`、`encryption=aes256`、`encrypt_names=true`、`password_version=2026-01`。
- **常见误用**：只保存密码而不记密码版本，导致历史批次恢复时无法通过配置匹配原密码。

<a id="cfg-delete_source"></a>
#### 校验通过后删除源文件（`delete_source`）

- **解决什么问题**：在归档已经可恢复后释放源目录空间。
- **什么时候开 / 不开**：只有在可以接受源文件被逐个删除、并且已安排外部归档保管时开启；默认关闭。
- **典型联动**：开启后后端强制 `归档后校验=true`，并在删除每个文件前重新检查成品 SHA-256、源文件身份和源内容 SHA-256；外部上传和成品清理仍由其他工具负责。
- **示例**：`verify=true`、`delete_source=true`，同时保留包外 `.sha256` 与清单目录。
- **常见误用**：把清单写入归档输出目录后再清理源文件；清单目录应与源目录和成品目录分离。

## 使用步骤

1. 在插件市场安装并启用“压缩归档”。
2. 打开插件配置，开启“启用归档服务”，创建任务并填写“源目录”“归档输出目录”和独立的“清单目录（可选）”。输出目录选择卷内子目录，例如 `/archive/ready`，不要直接选择独立卷挂载根。
3. 按需设置分组、`归档多少天之前的文件`、本地成品上限、`预留磁盘空间`、压缩格式、加密和清理选项；首次运行先使用“预览文件”确认候选文件与预计批次。
4. 保存配置后手动运行一次任务，确认历史清单已持久化、批次状态为已完成、包外清单和 `.sha256` 已生成。
5. 如果使用外部工具接力，可开启“自动分批续跑”并确认它会移走已发布成品；插件每 60 秒检查一次，但不把移走动作解释为上传成功。
6. 在恢复目录解压归档，使用包内 `SHA256SUMS` 校验文件和两份包内清单，再按清单中的相对路径恢复 `files/` 内容。

### MediaVault 本地接力配置样例

以下仅是本地目录接力的通用配置样例，不代表任何 NAS 或远端部署已经验证：

```yaml
source_dir: /data/source
output_dir: /data/archives
manifest_dir: /data/catalog
```

MediaVault 或其他外部工具可以读取 `/data/archives` 中已发布的成品，并把 `/data/catalog` 作为包外清单来源。插件不负责上传或清理成品，也不会因为成品被外部工具移走就推断上传成功；开启“自动分批续跑”后仅在空间允许时恢复处理队列。

## 注意事项 / 已知风险

- 归档包发布前会在输出目录旁的 `.archivemanager-staging` 中构建，暂存区和输出目录必须在同一文件系统；发布后在包外写入 `<批次 ID>.<格式>.sha256`。输出目录应是卷内子目录，例如 `/archive/ready`，不能直接使用独立卷挂载根。插件不会自动删除已发布归档、包外清单或历史批次。
- 包内固定包含 `files/`、`manifest.md`、`manifest.json` 和 `SHA256SUMS`。`SHA256SUMS` 覆盖所有源文件成员及 `manifest.md`、`manifest.json` 的摘要；包外 `.sha256` 只校验归档文件本身。
- 外部清单位于 `清单目录/<任务显示名>/`，包括每批次的 `.md`、`.json` 以及任务级 `index.md`、`index.json`；多个任务共用清单目录时，根目录会自动生成汇总 `index.md`、`index.json`，同名任务使用可读数字后缀区分。清单写入失败时批次会保留在待补全状态，不会开始源文件清理。
- 停止或进程中断后，插件保留已发布成品和账本；下一次运行会按历史优先顺序校验可恢复批次并补全文档。中断期间不会继续清理源文件。
- 未发布的失败或取消批次可在批次详情中重试；如果源文件版本或任务配置已经变化，插件会保留原失败记录并将其标记为“已替代”，再让未归档成员按新配置重新分批。已记录过归档摘要的成品即使被外部移走，也不会重新打包；应恢复原归档包，或只使用“补全清单”恢复包外文档。
- 如果外部工具移走或删除已发布成品，插件不会把此动作当作上传成功；开启“自动分批续跑”时只会在输出卷达到“预留磁盘空间”且本地成品上限满足时继续，源文件清理仍必须单独通过完整校验。
- 输出卷启动时无法满足“预留磁盘空间”时不会开始新构建；应改用有空间的其他卷或先清理空间，不要把独立卷挂载根改成输出目录来绕过检查。
- 开启“校验通过后删除源文件”具有破坏性。只要源文件缺失、被替换、内容摘要变化或没有权限删除，该文件会被保留并记录结果，不能把清理状态当成上传状态。
- 清理结果会分别记录 `missing`（源文件已不存在）、`changed`（文件身份或 SHA-256 与归档快照不符，保留当前文件）和 `failed`（无权限删除，保留当前文件）。这些状态不会计入已删除，也不会触发重打包。
- 源目录仅处理普通文件，不跟随符号链接；不要把需要保留链接语义的目录直接交给首版归档。

## 故障排查

- 主日志：`MoviePilot/config/logs/moviepilot.log`
- 插件日志：`MoviePilot/config/logs/plugins/archivemanager.log`
- 配置未生效：调用相对路径 `/summary` 查看 `config_error`，并检查三个任务目录是否为绝对路径、是否互相重叠，以及 Cron 和时区是否有效。
- 任务不继续：检查历史待办是否已达到“本地成品最多批次”或“本地成品最大体积”，以及输出卷是否达到“预留磁盘空间”；开启“自动分批续跑”时确认外部工具确实已移走成品。
- 启动时报空间错误：输出目录旁的 `.archivemanager-staging` 必须与输出目录同一文件系统；选择卷内子目录并为暂存和成品预留空间。
- 批次停在 `manifest_pending`：确认归档成品仍在输出目录，使用批次详情中的“补全清单”重新生成包外 `.md`、`.json` 和索引。
- 批次进入 `cleanup_failed`：查看批次清单中的逐文件结果和系统权限；插件不会因为删除失败而重建或删除归档包。
- 恢复加密批次失败：恢复任务当前密码，并把 `密码版本` 改回批次记录中的版本；密码错误会报告为校验失败，但日志和错误消息不会输出密码本身。
- `sha256sum -c SHA256SUMS` 失败：先确认归档包本身的包外 `.sha256`，再确认解压目录没有改动，并在同时包含 `SHA256SUMS` 的目录执行校验。macOS 可使用 `shasum -a 256 -c SHA256SUMS`。

## 致谢 / 参考

- 归档容器使用 7z 与 ZIP 标准格式；恢复端可使用支持对应格式和 AES 的 7-Zip 等标准工具。
- 7z 无法原样保留包含字面反斜杠（`\\`）的文件名；插件会拒绝这类批次而不会静默改写恢复路径。遇到这类文件名时请选择 `ZIP`。
- 归档包和包外清单均采用 UTF-8 文本，路径、文件摘要和恢复步骤以清单内容为准。
- 插件图标使用已安装的官方 Tabler Icons `archive` 图标，遵循 MIT License；仓库内的位图文件为 `icons/archivemanager.png`。
